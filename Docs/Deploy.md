# 배포 가이드 (Vercel)

> taxi-pitstopmap을 Vercel에 배포하는 순서입니다. 계정 로그인과 API 키 입력은 본인이 직접 해야 하는 단계입니다.

## 0. 배포 전 확인

- [ ] 배포할 코드가 `main` 브랜치에 있다 (Vercel 운영 배포는 `main` 기준)
- [ ] 로컬에서 `npm run build` 가 통과한다
- [ ] Supabase 마이그레이션이 모두 적용되어 있다 (`python data/scripts/apply_migrations.py` → "적용할 마이그레이션이 없습니다.")
- [ ] Supabase에서 **Authentication → Sign In / Providers → Allow anonymous sign-ins** 가 켜져 있다 (제보 기능)

## 1. Vercel 프로젝트 만들기

1. https://vercel.com 에 **GitHub 계정으로 로그인**합니다.
2. **Add New… → Project** 를 누르고 `jeongsemin/taxi-pitstopmap` 저장소를 가져옵니다. (GitHub 저장소 접근 권한 허용이 필요합니다)
3. 설정 화면에서 아래처럼 둡니다. (대부분 자동으로 잡힙니다)
   - Framework Preset: **Next.js**
   - Root Directory: 기본값 (저장소 루트)
   - Production Branch: **main**

> ⚠️ **"여러 서비스(Services)"로 가져오지 마세요.** 저장소에 Python 데이터 스크립트 폴더(`data/`)가 있어서 Vercel이 "Multiple applications detected… Services" 화면을 띄우고 `vercel.json`을 요구할 수 있습니다. 목록에서 **`app` (Next.js, 경로 `/`)** 항목의 **Import single project** 를 눌러 Next.js 앱 하나만 가져오세요. `data/` 는 내 PC에서만 쓰는 스크립트라 배포 대상이 아닙니다.

## 2. 환경변수 4개 등록

**Deploy 를 누르기 전에** Environment Variables 에 아래 4개를 넣습니다. 값은 로컬 `.env.local` 에서 복사합니다.

| 이름 | 값 | 비고 |
| ---- | -- | ---- |
| `NEXT_PUBLIC_KAKAO_MAP_KEY` | 카카오 **JavaScript 키** | 브라우저에 공개되는 값 |
| `KAKAO_REST_API_KEY` | 카카오 **REST API 키** | **서버 전용**. 이름에 `NEXT_PUBLIC_` 을 붙이지 마세요 |
| `NEXT_PUBLIC_SUPABASE_URL` | `https://<프로젝트ID>.supabase.co` | `/rest/v1/` 같은 경로는 빼고 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase publishable(anon) 키 | 브라우저에 공개되는 값 |

> ⚠️ **등록하지 않는 것**: `SUPABASE_DB_PASSWORD`, `SUPABASE_DB_HOST` 는 데이터 적재 스크립트(`data/scripts/`)를 내 PC에서 돌릴 때만 쓰는 값입니다. 앱 서버에는 필요 없고, 넣으면 노출 위험만 커집니다.

환경변수를 바꾸면 **다시 배포(Redeploy)해야** 반영됩니다.

## 3. 배포하고 주소 확인

**Deploy** 를 누르면 몇 분 안에 `https://<프로젝트이름>.vercel.app` 형태의 주소가 생깁니다. 이 주소가 **운영 주소**입니다.

> Vercel 개요에 **"No Production Deployment — push to the main branch"** 라고 나오면 첫 배포가 아직 시작되지 않은 것입니다. 가져오기 마지막 단계(통합 검토 후 Deploy)를 끝내거나, `main` 브랜치에 새 커밋을 병합하면 자동으로 배포가 시작됩니다. 이후에는 `main`에 병합될 때마다 자동으로 운영 배포가 갱신됩니다.

> Vercel은 배포(커밋)마다 임시 미리보기 주소도 만듭니다. 카카오에는 **바뀌지 않는 운영 주소 하나**만 등록해서 쓰세요.

## 4. 카카오 개발자 콘솔에 도메인 등록 (필수)

이 단계를 하지 않으면 **지도가 뜨지 않습니다.**

1. 카카오 개발자 콘솔 → 내 애플리케이션 → **앱 설정 → 플랫폼 키** → **JavaScript 키** 선택
2. **JavaScript SDK 도메인**에 운영 주소(`https://<프로젝트이름>.vercel.app`)를 추가하고 저장합니다. (기존 `http://localhost:3000` 은 그대로 둡니다)
3. **REST API 키에는 허용 IP를 걸지 마세요.** Vercel 서버의 IP는 고정되어 있지 않아서 걸면 식당 조회가 막힙니다.

## 5. 배포 확인 (실제 휴대폰에서)

운영 주소를 휴대폰에서 열어 아래를 확인합니다.

- [ ] 지도가 뜬다 (안 뜨면 4번 도메인 등록 확인)
- [ ] 위치 권한 요청이 뜨고, 허용하면 내 위치 기준으로 장소가 나온다 (HTTPS 에서만 위치가 동작합니다)
- [ ] 식당·화장실 마커, 주차 가능 필터, 마커 묶음이 동작한다
- [ ] 장소 상세에서 카카오맵 / 네이버 지도 / T맵 버튼이 앱으로 연결된다 (출발지가 현재 위치로 잡히는지 확인)
- [ ] 제보 버튼이 동작하고 점수가 바뀐다
- [ ] 안드로이드 뒤로가기 버튼이 상세만 닫는다

## 문제 해결

| 증상 | 확인할 것 |
| ---- | -------- |
| 지도가 회색/빈 화면 | 카카오 콘솔의 JavaScript SDK 도메인에 운영 주소가 정확히 들어갔는지 (`https://` 포함, 끝에 `/` 없이) |
| "장소를 불러오지 못했어요" | Vercel 환경변수 4개가 모두 들어갔는지, 넣은 뒤 Redeploy 했는지. Vercel 프로젝트의 Logs 에서 `/api/places` 오류 확인 |
| "요청이 많아 잠시 후 다시 시도해 주세요" | IP당 1분 40회 제한에 걸린 것입니다. 잠시 후 다시 시도 |
| 제보가 "로그인에 실패했어요" | Supabase 에서 익명 로그인(Allow anonymous sign-ins)이 꺼져 있는지 |
| 점수가 전부 "점수 없음" | 서울 밖입니다. 주차장 데이터는 현재 서울에만 있습니다 |

## 6. 악용 대응 (공개 전 점검)

코드와 DB 에 넣은 방어:
- `/api/places`: IP당 1분 40회 + 서버 인스턴스 전체 1분 300회 제한, 좌표 범위·반경 검증, CDN 캐시
- 제보(`reports`): 본인 것만 읽기/쓰기(RLS), 같은 장소 10분 재제보 금지, 하루 30건 제한, 입력 형식 검증(장소 id 형식·이름 길이·한국 좌표·내용 200자, `0006` 마이그레이션)

**직접 설정해야 하는 것** (대시보드에서):
- [ ] Supabase → Authentication → **Rate Limits** 에서 익명 로그인(Anonymous sign-ins)의 시간당 한도를 확인 (기본값은 IP당 시간 30회). 계정을 무한히 만들어 제보를 부풀리는 것을 막는 핵심 설정입니다.
- [ ] (선택) Vercel → Firewall 에서 `/api/places` 경로에 IP별 호출 제한 규칙 추가. 서버리스 인스턴스와 상관없이 막아 줍니다.
- [ ] (선택) 악용이 보이면 Supabase → Authentication → Attack Protection 의 CAPTCHA(Turnstile 등)를 익명 로그인에 켭니다. 앱에 토큰 전달 코드가 필요하니 요청해 주세요.

남아 있는 한계: 익명 로그인 구조라 계정을 여러 개 만드는 사용자가 한 장소에 제보를 2건 이상 넣으면 점수가 최대로 움직입니다. 위 한도와 CAPTCHA 로 비용을 올릴 수는 있어도 완전히 막지는 못합니다. 실제 악용이 보이면 제보자 위치 확인이나 신뢰 등급(`profiles.trust_level`) 도입을 검토하세요.

## 7. 오류 모니터링

서버와 화면에서 난 오류가 Supabase `error_logs` 테이블에 쌓입니다. 외부 서비스 가입은 필요 없고, 좌표·IP·사용자 계정은 저장하지 않습니다(경로와 짧은 브라우저 정보만).

**무엇이 기록되나**

| 종류(kind) | 언제 |
| ---------- | ---- |
| `map_sdk_load` | 카카오 지도를 불러오지 못했을 때 (도메인 미등록·잘못된 키 등) |
| `places_fetch` | 화면에서 장소 조회가 실패했을 때 (호출 제한 429 는 제외) |
| `places_failed` / `places_partial` / `score_failed` | 서버에서 장소 조회 전체/일부 실패, 점수 계산 실패 |
| `report_submit` | 제보 저장 실패 (중복·하루 한도 안내는 제외) |
| `js_error` / `unhandled_rejection` / `render_error` | 화면 자바스크립트 오류, 처리되지 않은 비동기 오류, 화면 그리기 오류 |

**보는 방법**
- 프로젝트 루트에서 `python data/scripts/show_errors.py` (최근 24시간 요약 + 최근 10건). `--hours 72`, `--latest 30` 으로 바꿀 수 있습니다.
- 또는 Supabase 대시보드 → Table Editor → `error_logs`.
- 배포 후 한 번은 확인하세요. 특히 `map_sdk_load` 가 보이면 카카오 도메인 등록을 먼저 의심합니다. `release` 열은 오류가 난 배포의 커밋 앞자리입니다.

**제한과 한계**
- 쓰기는 `log_error()` 함수로만 되고 앱은 읽을 수 없습니다. 이 함수는 공개 키로 누구나 부를 수 있어서, 1분 60건·하루 5,000건을 넘으면 기록하지 않고 버리며 30일이 지난 기록은 지웁니다. 그래서 누군가 일부러 가짜 오류를 보내 **잡음을 섞는 것은 막지 못합니다.**
- 한 화면(세션)에서 보내는 오류는 최대 10건이고 같은 오류는 한 번만 보냅니다. 앱이 완전히 로딩되기 전에 죽는 경우나 오프라인에서 난 오류는 기록되지 않습니다.
- **알림은 없습니다.** 오류가 쌓여도 자동으로 알려 주지 않으니 주기적으로 확인해야 합니다. 알림이 필요해지면 Sentry 같은 서비스를 붙이는 것을 검토하세요. 스택 추적(소스맵), 이메일 알림, 사용자 영향 집계는 이 방식에 없습니다.

## 8. 개인정보·위치정보 안내와 위치정보 이용 동의

**구성**
- 위치를 읽기 전에 **동의 화면**(첫 방문, "내 위치" 버튼, 설정 탭의 "동의하기")을 보여 주고, "동의하고 내 위치 사용"을 눌러야만 위치를 요청합니다. 동의하지 않으면 강남역 기준으로 씁니다.
- **철회**: 설정 탭 → 위치정보 이용 동의 → 동의 철회. 철회하면 더 이상 위치를 읽지 않고 강남역 기준으로 돌아갑니다.
- **재동의**: 동의 문구를 바꿀 때 `src/lib/legal.ts`의 `LOCATION_CONSENT_VERSION`(날짜)을 올리면 이전 동의가 무효가 되어 모두에게 다시 동의를 받습니다. 문구를 바꾸고 버전을 올리지 않으면 이전 동의가 그대로 유효한 것으로 남으니 주의하세요.
- **동의 기록**: `consent_logs` 테이블에 브라우저가 만든 무작위 번호, 문구 버전, 동의·거부·철회, 시각만 남깁니다. IP, 위치, 계정은 저장하지 않아 **누가 동의했는지는 알 수 없습니다.** 증빙이라 자동으로 지우지 않습니다. 보려면 Supabase 대시보드 → Table Editor → `consent_logs`.
- 안내 화면은 `/privacy`(설정 탭, 제보 영역, 동의 화면에서 연결)입니다.

**⚠ 법적 충분성은 보증되지 않습니다.** 이 구현은 동의를 받는 기술적 절차(요청 전 동의, 항목 분리, 기록, 철회, 재동의)를 갖춘 것이고 법률 검토를 거친 문서가 아닙니다. 현재 운영 설정에서 부족할 수 있는 점:
- **운영자 정보**: 서비스명 "쉼터지도"와 GitHub 문의 링크만 표시합니다. 위치정보 이용약관에는 일반적으로 사업자(운영자)의 이름·주소·연락처가 들어갑니다.
- **위치정보관리책임자**: 지정·표시하지 않았습니다.
- **만 14세 미만**: 이용 제한이나 법정대리인 동의 문구를 넣지 않았습니다.
- **사업 신고**: 위치기반서비스사업 신고가 필요한지 확인하지 않았습니다.
- 동의 항목을 하나로 묶어 두었고(위치 이용 + 제3자 제공 안내), 약관 전문을 별도로 두지 않았습니다.

널리 공개하거나 상업적으로 운영하기 전에, 위 항목을 포함해 위치정보법·개인정보보호법상 의무가 있는지 전문가나 관련 기관(방송통신위원회, 한국인터넷진흥원 등)에 확인하세요. 운영자 정보를 넣으려면 `src/lib/legal.ts`의 `CONTACT_URL`과 동의 문구를 고치고 버전을 올리세요.

앱의 동작이 바뀌면(분석 도구 추가, 위치 저장, 로그인 추가 등) 동의 문구와 `/privacy` 글도 같이 고치세요.

## 9. 카카오 API 한도 대비

**먼저 알아둘 사실 (직접 측정)**
- 서울 12곳(번화가와 외곽)에서 새로 조회해 보니 **한 번에 카카오 로컬 API를 정확히 20번(상한) 불렀습니다.** 서울은 어디서든 반경 500m 안 식당이 45곳을 넘어서 격자 조회로 넘어가기 때문입니다.
- 따라서 **하루에 새로 조회할 수 있는 횟수 ≈ 카카오 하루 한도 ÷ 20** 입니다. 예를 들어 하루 한도가 10만 건이면 하루 5,000번 조회가 한계입니다. 캐시가 잘 맞을수록 이보다 많이 받을 수 있습니다.
- **하루 한도 숫자는 제가 확인하지 못했습니다.** 카카오 개발자 콘솔의 앱 → 통계(쿼터)에서 로컬 API의 실제 한도와 사용량을 확인하세요. 한도를 늘려야 하면 같은 콘솔에서 가능한지 확인하세요.

**이미 넣은 대비**
| 대비 | 효과 |
| ---- | ---- |
| CDN 캐시 2분 (같은 주소의 응답을 모든 서버가 나눠 씀) | 같은 지역을 다시 보는 요청은 서버·카카오를 부르지 않음. 가장 효과가 큼 |
| 서버 메모리 캐시 30분 | 같은 장소·반경을 다시 조회해도 카카오를 안 부름 (서버 인스턴스마다 따로) |
| 카카오 실패 시 옛 결과로 대체 (최대 6시간) | 카카오가 잠시 실패해도 식당이 사라지지 않음 |
| 한도 초과(429) 감지 → 10분간 호출 중단 | 소용없는 호출로 한도를 더 쓰지 않음. 이때 식당 대신 "지금 식당 조회가 몰려서 잠시 쉬고 있어요" 안내가 나오고 화장실은 계속 보임 |
| 일부 칸이 실패한 결과는 1분만 캐시 | 덜 받은 결과가 오래 남지 않음 |
| IP당 분당 40회, 서버 인스턴스당 분당 300회 제한 | 한 사용자·한 서버가 한도를 몰아 쓰지 못함 |

**쓰는 양 확인하기**
- `python data/scripts/show_usage.py --budget <하루 한도>` 로 일별 호출 수, 새로 조회한 건수, 조회당 호출 수, 한도 대비 비율을 봅니다.
- 이 숫자는 **참고용**입니다. 공개 키로 누구나 값을 부풀릴 수 있어서 앱은 이 값으로 기능을 막지 않습니다. 정확한 사용량은 카카오 콘솔로 확인하세요.
- 한도 초과가 실제로 일어나면 `error_logs`에 `kakao_quota` 종류로 남습니다 (`show_errors.py`).

**한도가 빠듯해지면: `KAKAO_MAX_CALLS` 환경변수**
- 조회 한 번에 쓰는 카카오 호출 상한입니다 (기본 20, 3~40). Vercel 환경변수에 넣고 Redeploy 하면 적용됩니다.
- 낮출수록 호출은 줄지만 반경 안 식당을 덜 받아 옵니다. 받는 식당 수는 호출 수에 대략 비례합니다(추정). 예: 20회에 약 250곳이면 10회에는 약 125곳 안팎입니다.

**한계**
- 서버 메모리 캐시와 호출 제한은 서버 인스턴스마다 따로라서 분산된 대량 호출은 완전히 막지 못합니다.
- **한도 초과 응답이 HTTP 429라는 것은 카카오 문서를 근거로 한 가정입니다.** 실제로 초과된 적이 없어서 시험해 보지 못했고, 모의 환경에서만 동작을 확인했습니다. 실제 한도가 초과되면 `error_logs`와 화면 안내가 의도대로 나오는지 확인하세요.
- 브라우저의 카카오 지도 불러오기(Maps JS SDK)의 한도는 로컬 API와 별개이고, 이 앱은 따로 대비하지 않았습니다.
- 화장실·주차장은 우리 DB에서 조회하므로 카카오 한도와 무관합니다.

## 알아둘 점

- **호출 제한은 서버 인스턴스별 메모리 방식**이라 서버리스에서는 인스턴스마다 따로 셉니다. 한 사용자의 반복 호출은 막지만, 분산된 대량 호출까지 막으려면 Redis 같은 공유 저장소나 Vercel 방화벽 규칙이 필요합니다.
- 조회 한 번이 카카오 로컬 API를 최대 20회 호출합니다. 카카오 콘솔의 **일일 호출 한도**를 확인하고, 사용량을 지켜보세요.
- Vercel **Hobby 플랜은 비상업적 용도** 기준으로 알고 있습니다. 서비스를 판매·상업적으로 운영할 계획이라면 플랜과 약관을 확인하세요. (제가 약관을 직접 확인하지는 못했습니다)
- 카카오 로컬 API 결과를 DB에 저장해 쓰는 것(주차장 데이터)이 카카오 이용약관상 허용되는지도 상용화 전에 확인하세요.
