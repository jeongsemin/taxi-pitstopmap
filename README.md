## 📌 프로젝트 소개

택시 기사는 식사와 화장실이 급해도, 근처에 식당이나 화장실이 있더라도 **차를 세울 곳이 없어** 헤매거나 주정차 단속을 걱정해야 합니다.
기존 지도 앱은 "장소"는 알려주지만 "그 앞에 차를 세울 수 있는지"는 알려주지 않습니다.

**taxi-pitstopmap**은 현재 위치에서 _차를 세우고 바로 이용할 수 있는_ 식당과 화장실을 보여줍니다.

## 🎯 프로젝트 목표

- 실제 택시 기사의 불편을 해결하는 서비스 구현
- 바이브 코딩(AI 활용 개발) 학습 및 개발 과정 기록
- 동작하는 데모와 실사용자 피드백 확보

## 🧠 핵심 아이디어: 주정차 점수

주정차 가능 여부를 직접 제공하는 무료 API는 없기 때문에, 세 가지 데이터를 조합합니다.

| 데이터 층   | 출처                                              | 신뢰도               |
| ----------- | ------------------------------------------------- | -------------------- |
| 공식 데이터 | 공공주차장, 주정차 허용/금지 구간                 | 높음 (커버리지 낮음) |
| 추정 데이터 | 자체 주차장 여부, 인근 공영주차장 거리, 도로 유형 | 중간                 |
| 사용자 제보 | 기사들의 "세울 수 있음 / 단속됨" 제보             | 시간이 갈수록 높아짐 |

**설계상 점수 예시**: 자체 주차장(+40) + 100m 내 공영주차장(+30) + 최근 30일 내 "가능" 제보(+30) − "단속됨" 제보(−40)

**현재 구현된 점수** — 택시 기사는 공영주차장을 잘 쓰지 않으므로 "주차 자리 제공 → 도로변 주차" 순으로 봅니다.

| 구분 | 근거 | 점수 |
| ---- | ---- | ---- |
| 주차 자리 제공 (가장 큰 값 하나) | 제보 2명 이상 / 1명 | 60 / 50 |
| | 가게와 이름이 겹치는 민영주차장 150m 이내 (추정) | 40 |
| | 같은 건물(주소 끝 일치)이거나 30m 이내 민영주차장 (추정) | 30 |
| 도로변 주차 (최대 45) | 노상주차장 100m 이내 | +30 |
| | '도로변에 세움' 제보 1명 / 2명 이상 | +15 / +30 |
| 보조 | 공영주차장 200m 이내 / 다른 민영주차장 100m 이내 / 주변 주차장 10곳 이상 | 각 +5 |
| 감점 | 🔴 단속됨 1명 / 2명 이상 | −20 / −40 |
| | ⚪ 세울 곳 없었음 1명 / 2명 이상 | −10 / −15 |

합계는 0~100점으로 제한, 🟢 60 이상 · 🟡 30~59 · 🔴 30 미만. 그래서 🟡 이상은 주차 자리 제공이나 도로변 주차의 근거가 있는 곳이고, 주변에 주차장이 많다는 것만으로는 🟡이 되지 않습니다. "주차 가능" 필터는 🟡 이상(30점 이상)입니다. 이름에 '거주자'가 들어간 주차장(거주자우선·전용)은 외부 차량이 쓸 수 없어 뺍니다. 규칙은 [`supabase/migrations/0008_store_and_roadside_parking.sql`](supabase/migrations/0008_store_and_roadside_parking.sql)의 `score_places()` 한 곳에서 조정합니다.

**제보 종류**: 🟢 주차 자리 제공됨 · 🟢 도로변에 세움 · 🔴 단속됨 · ⚪ 세울 곳 없었음 (최근 30일, 서로 다른 사용자 수 기준). 제보가 쌓이면 이름·주소로 한 추정보다 제보가 우선합니다.

**한계 (중요)**: 가게가 주차 자리를 제공하는지 알려 주는 공공데이터는 없습니다. 현재는 카카오 주차장 데이터의 이름·주소·거리로 "추정"만 하며, 서울 식당 약 1,400곳을 살펴보니 추정 근거가 있는 곳이 약 48%, 근거가 없는 곳이 약 52%였습니다. 도로변은 주정차 허용·금지 구간 데이터가 없어서 노상주차장(도로에 그어진 주차구획)과 제보로 판단하고, 서울시 고정형 단속 카메라(약 4,700곳)가 60m 안에 있으면 "도로변에 세우면 단속될 수 있어요"라고 경고만 표시합니다(점수는 바꾸지 않음). 카메라는 어린이보호구역 등 일부 지점에만 있고 이동식 단속은 빠져 있어서, 카메라가 없다는 것이 세워도 된다는 뜻은 아닙니다. 실제로 세울 수 있는지는 제보가 쌓여야 정확해지며, 화면에도 "추정, 현장 확인 필요"라고 안내합니다. 가중치는 가정값이고 실제 기사 피드백으로 검증되지 않았습니다.

**데이터가 없는 지역은 "점수 없음"(⚪)**: 장소 반경 500m 안에 주차장 데이터가 하나도 없으면 🔴가 아니라 점수 없음으로 표시하고 안내를 띄웁니다. (현재 주차장 데이터는 서울 전역(카카오 주차장 약 9,300곳)이고, 서울 밖은 "세울 수 없음"이 아니라 "알 수 없음"입니다. 화장실도 서울 전역입니다: 공공데이터 약 5,400곳 + OSM 보강.) 이런 지역에 제보가 있으면 중립 30점에서 제보만큼 가감합니다.

## 🚀 시작하기

> 개발 초기 단계로, 아래 내용은 구현 진행에 따라 업데이트됩니다.

### 요구 사항

- Node.js 20 이상 (LTS 권장)
- Python 3.11 이상 (데이터 적재 스크립트용)
- 카카오 개발자 계정: JavaScript 키, REST API 키, 웹 플랫폼에 `http://localhost:3000` 등록, 카카오맵 사용 설정
- Supabase 프로젝트 (PostGIS 사용, 제보 기능은 Authentication → Sign In / Providers 에서 **Allow anonymous sign-ins** 활성화 필요)

### 설치 및 실행

```bash
git clone https://github.com/jeongsemin/taxi-pitstopmap.git
cd taxi-pitstopmap
npm install
cp .env.example .env.local   # 환경변수 입력
npm run dev
```

### 환경변수

```
NEXT_PUBLIC_KAKAO_MAP_KEY=          # 카카오 JavaScript 키
KAKAO_REST_API_KEY=                 # 카카오 REST API 키 (서버 전용)
NEXT_PUBLIC_SUPABASE_URL=           # https://<프로젝트ID>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=      # publishable(anon) 키
SUPABASE_DB_PASSWORD=               # 데이터 적재 스크립트 전용
SUPABASE_DB_HOST=                   # IPv4 환경에서 Session pooler 호스트 (선택)
```

> ⚠️ `.env` 파일은 절대 커밋하지 말것. `SUPABASE_DB_PASSWORD`에는 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다.

### 데이터 준비

앱은 Supabase DB에 적재된 화장실·주차장 데이터를 사용합니다. 프로젝트 루트에서 실행합니다.

```bash
pip install -r data/requirements.txt
python data/scripts/apply_migrations.py        # 테이블·함수 생성
python data/scripts/load_osm_toilets.py --area 서울특별시 --level 4   # OSM 화장실 (서울 전체)
python data/scripts/load_public_toilets.py --csv data/raw/공중화장실정보_서울특별시.csv   # 공공데이터 화장실 (CSV 필요, 카카오 주소 변환)
python data/scripts/load_parking_lots.py --region seoul   # 카카오 주차장 (서울, 카카오 호출 약 2천 회)
python data/scripts/load_enforcement_cameras.py   # 주정차 단속 카메라 위치 (CSV 필요)
```

- 공공 화장실 CSV는 공공데이터포털 [전국공중화장실표준데이터](https://www.data.go.kr/data/15012892/standard.do)의 다운로드 버튼으로 내려받아(주소를 직접 입력하면 403) `data/raw/`에 저장합니다. (`data/raw/`는 커밋되지 않습니다)
- 단속 카메라 CSV는 서울 열린데이터광장 [OA-20471](https://data.seoul.go.kr/dataList/OA-20471/S/1/datasetView.do)의 '내려받기(CSV)'로 받아 `data/raw/cctv_seoul.csv`(cp949)로 저장합니다. 분기마다 갱신되니 다시 받아 같은 명령으로 교체하세요.
- 원천 데이터에 좌표가 없어 카카오 주소 검색으로 지오코딩합니다.
- Supabase 직접 접속은 IPv6 전용이라 IPv4 환경에서는 `SUPABASE_DB_HOST`에 Session pooler 호스트를 지정합니다.

## 📝 개발 기록

- **공중화장실 좌표 제거**: 공공데이터 원천에서 2025년 2월부터 위·경도가 빠져 카카오 주소 검색으로 지오코딩했습니다. 390건 중 381건(98%)이 변환되었습니다.
- **Supabase IPv6**: 직접 접속 주소가 IPv6 전용이라 IPv4 환경에서는 Session pooler 호스트로 접속합니다.
- **카카오 45건 한도**: 카테고리 검색은 한 번에 최대 45건이라 주차장은 영역을 타일로 나눠 조회하고, 한도에 걸리면 4등분해 재조회합니다.
- **식당 조회와 한도**: 반경 안 식당이 매우 많아(강남역 500m 826곳, 1km 1,980곳, 2km 5,376곳) 45건만 받으면 중심 주변만 보였습니다. 이제 반경을 격자 칸으로 나눠 가까운 칸부터 한 번에 최대 24회까지 호출해 약 320곳까지 받아 오고, 전부 받지 못하면 실제 개수와 함께 화면에 안내합니다. 반경이 커도 호출 상한 때문에 중심 약 400m까지만 채워지는 한계가 있습니다. 같은 위치 조회는 서버에서 1분간 캐시합니다.
- **조회 실패 표시**: 장소를 불러오지 못하면 지도·목록에 오류 문구와 "다시 시도" 버튼을 보여 주고, 이전 결과가 남아 있으면 그 사실도 알립니다.
- **마커 겹침과 터치 영역**: 식당이 수백 곳이라 마커가 겹쳐서, 카카오맵 클러스터 라이브러리로 멀리서 볼 때 식당을 숫자 원으로 묶습니다(묶음을 누르면 확대, 더 확대하면 개별 마커). 🟢 주차 가능 식당, 화장실, 선택한 장소는 묶지 않고 항상 개별로 보입니다. 마커의 보이는 크기는 23px로 두고, 투명 여백으로 눌리는 영역만 40px로 넓혔습니다.
- **뒤로가기**: 장소 상세를 열 때, 그리고 지도에서 목록·설정 탭으로 갈 때 브라우저 기록을 한 칸 쌓아, 모바일 뒤로가기 버튼이 사이트를 벗어나지 않고 상세 → 목록/설정 → 지도 순으로 한 단계씩 돌아갑니다. 목록↔설정 이동은 기록을 쌓지 않고 바꿔 끼웁니다.
- **일부만 실패해도 보여 주기**: 식당(카카오)과 화장실(DB) 중 한쪽이 실패해도 나머지는 보여 주고 "나머지만 보여 드려요" 안내와 재시도 버튼을 띄웁니다. 점수 계산만 실패한 경우도 안내합니다. 요청한 종류가 전부 실패할 때만 오류로 처리합니다.
- **위치 확인 대기**: 위치 확인이 끝나기 전에는 장소를 조회하지 않아, 위치 권한을 허용한 사용자에게 강남역 결과가 먼저 보였다 바뀌지 않습니다. 확인이 8초 넘게 걸리면(권한 창이 열려 있는 등) 기본 위치로 먼저 보여 주고, 위치가 확인되면 그 위치로 다시 조회합니다.
- **API 호출 보호** (`/api/places`): 조회 한 번이 카카오를 최대 20회 호출하므로 공개 배포 전에 보호를 넣었습니다. ① 입력 검증: 한국 밖 좌표는 400, 반경은 최대 3km ② IP당 1분 40회 제한(초과 시 429와 `Retry-After`) ③ 좌표를 약 11m 단위로 맞추고 응답에 `s-maxage=30` 캐시 헤더를 붙여 같은 지역 조회를 CDN이 공유, 식당 목록은 서버에서 5분 캐시. 제보 직후 다시 불러올 때는 캐시를 건너뜁니다. 부분 실패 응답은 캐시하지 않습니다. **호출 제한은 서버 인스턴스별 메모리 방식이라 서버리스에서는 인스턴스마다 따로 세므로, 분산된 공격까지 막으려면 Redis 같은 공유 저장소나 Vercel 방화벽 규칙이 필요합니다.**
- **데이터 중복**: 공식 화장실과 30m 이내로 겹치는 OSM 항목은 공식 데이터를 남기고 제거합니다.
- **길안내는 직접 제공하지 않습니다**: 목적지를 카카오맵(웹 링크), 네이버 지도(공식 URL 스킴 nmap://route/car), T맵(커뮤니티에서 알려진 tmap://route 스킴)으로 넘겨 각 앱에서 안내받습니다. 앱 스킴은 앱이 설치된 휴대폰에서만 열리고, 열리지 않으면 안내 문구를 띄웁니다. 네이버 지도는 출발지를 넘기지 않는데 현재 위치를 쓰는지 문서에서 확인하지 못했고, T맵 스킴은 기기·앱 버전에 따라 다를 수 있어 실기기 검증이 필요합니다.
- **마이그레이션 이력**: 함수 반환 타입을 바꾸는 변경이 생겨 `schema_migrations` 테이블로 적용 이력을 기록합니다.
- **제보 인증**: 운전 중 사용성을 위해 가입 없이 익명 로그인을 사용합니다. 제보자 ID는 본인만 조회할 수 있고(RLS), 점수 집계는 `security definer` 함수가 하며, 같은 장소 10분 재제보 금지·하루 30건 제한으로 어뷰징을 줄입니다. 카카오 로그인은 추후 연결 예정입니다.
- **화면 테마**: Figma 다크 디자인을 기본으로 하고, 설정 탭에서 자동(기기 설정)·라이트·다크를 고를 수 있습니다. 라이트는 카카오 옐로우(#FEE500)와 검정 텍스트, 흰 면 중심으로 구성했고 지도는 카카오맵 기본 타일을 그대로 씁니다. 색은 src/app/globals.css 의 토큰 한 곳에서 관리합니다.
